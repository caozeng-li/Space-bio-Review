# SpaceBioReview

科学项目评审系统。主审从申请识别开放的知识问题，安排持续工作的专题作者；专题作者阅读、咨询并直接发布科学稿。主审依据选定稿件形成正式评价，程序计算制度结果并装配报告。科学认知沿“原始材料 → 来源解释 → 项目论证 → 整体判断”传递，各层解释与其原文一起保存。

## 运行

```powershell
uv sync
uv run spacebio-review --application data/sample1.md --output runs/my-review
```

附件通过重复的 `--attachment` 指定。凭据按 `.env.example` 配置。每次运行使用新的空输出目录。`spacebio_review.read_result(path)` 可读取已有结果；持久化资料、稿件和状态用于阅读与追溯，不提供进程结束后的续跑。

## 科学认知的传递

1. **材料准备与准入。** 解析申请及附件，保留章节、段落、表格、图注和原页。最低准入判断是否具备可评审内容；可选的计划书内容形式审查由 `admission.yaml` 控制。
2. **主审理解项目。** 主审读取申请，辨认对象、安排、比较、读出和可能获得的知识。用开放职责安排专题作者，交付相关申请原句、预期用途和专业能力。核心知识贡献默认由主审持续负责，也可明确委派。
3. **专题作者独立研究。** 作者持有完整申请及持续职责，自行确定当前问题。可检索外部资料、直接读简短原文，或委派单来源读者深入解释关键材料。科学问题、作者会话和稿件版本分别有明确身份。
4. **单来源阅读。** 同一专题对同一来源的追问复用该来源读者。读者收到来源及待解释问题，解释来源内部的对象、条件、处理、比较、结果与能力关系；申请材料由专题作者持有。读者可继续阅读正文、附件及原页，普通正文回复直接成为阅读稿。
5. **解释与原文共同交接。** 阅读稿被标为评审解释，随同实际读到的原文快照和图像位置交回。交接不以稿件最终引用了哪些段落决定原文可用范围。专题作者据来源解释、原文和申请建立项目知识联系，区分申请已有安排、外部已有能力和拟议适配路径。
6. **定向协作与持续发布。** 作者可向其他作者提出具体关系问题，附上答案用途、申请原句和有关稿件。对方用现稿或新研究回答。等待具体答复时释放执行名额；答复到达后继续同一研究。`contribute(publish, content=完整正文)` 原样保存科学稿并通知相关作者，随后可继续研究。普通正文也可直接交付并结束；已有稿足够时 `finish_research` 复用现稿。
7. **选文与正式决定。** 主审按精确版本选择科学稿及顺序。正式评价读取申请、当前项目理解、有序科学稿、来源解释和关键原文，形成逐项理由与决定。国标总分、档位和制度结论由代码计算。主审随后根据这份已确定的决定写摘要和综合判断。
8. **装配与翻译。** 程序将选定科学稿原文、逐项评价、摘要和综合装配成中文报告，统一引用并保留段落来源。英文开启时翻译已确定的主文。中文先交付，翻译失败不会删除中文成果。

研究和发布共用同一作者会话。轮数、预算或上下文容量不足时，会话收到当前成果的发布要求，沿同一协议交付；需要继续研究时，以已发布完整稿、选入的完整原文单元及尚未吸收的新消息重组上下文。原生工具调用与结果按实际顺序进入会话，图像按接收模型能力传递并计价。目录可见不表示原文已经读过。

普通阅读窗口为 16,000 tokens，上限 32,000。窗口保留原生材料单元及相关章节、表格与图注上下文，需要更多内容时继续阅读。原文累计存档与当前会话实际容纳的原文分开管理。稿件记录已吸收的消息位置，生成期间后到的咨询答复仍作为新材料进入下一轮。

## 结构

| 模块 | 职责 |
|---|---|
| `cli.py`、`runner.py`、`v5/entry.py` | 公共入口、材料准备、准入与运行对象组装 |
| `evidence/`、`agents/reading.py` | 检索获取、结构解析、完整单元阅读、原页访问 |
| `v5/chief.py`、`topic.py`、`source_reading.py` | 主审、专题和单来源阅读职责 |
| `v5/session.py`、`conversation.py` | 持续研究会话、原稿发布、上下文容量管理 |
| `v5/collaboration.py`、`scientific_handoff.py` | 定向咨询、稿件与实际阅读原文交接 |
| `v5/records.py`、`research_context.py` | 问题、作者、稿件、原文身份及上下文组装 |
| `v5/report_composition.py`、`assessment.py` | 稿件冻结、正式评价和同一决定的综合 |
| `review/`、`publication/`、`v5/delivery.py` | 评价体系、计分、引用、报告装配及翻译 |
| `models/`、`v5/budget.py` | 模型适配、调度、消费计量和交付资源预留 |

模型负责理解资料、发现知识联系、提出问题、解释适用条件并作科学判断。代码负责身份、版本、原文载入、并发、预算、计分与装配。专题稿不会在出版时再交给另一位模型作者整体改写。

## 配置

| 文件 | 用途 |
|---|---|
| `config/review.yaml` | 评价体系、外部研究开关、专题并发数、历史截止日期 |
| `config/runtime.yaml` | 唯一模型与运行配置：角色、辅助模型、请求并发、预算、会话容量 |
| `config/expertise.yaml` | 学科与方法能力目录 |
| `config/evidence.yaml` | 检索、获取、缓存和阅读窗口 |
| `config/admission.yaml` | 最低准入与计划书内容形式审查 |
| `config/reporting.yaml` | 英文报告开关和翻译分批大小 |

默认模型：主审、专题及翻译使用 `deepseek-v4-pro`；来源读者与视觉辅助使用 `qwen3.5-397b-a17b`；准入与重排使用 `deepseek-v4.1-flash`。所有模型明确设置 `enable_thinking: false`。文本作者需要原页解释时可调用视觉辅助；具备视觉能力的来源读者直接接收原页图像。

当前默认采用 `gbt42048_2022`，启用外部研究，最多同时执行 4 个专题。改为 `general` 使用通用定性体系。会话容量：主审 256,000 tokens，专题作者 128,000，来源读者 64,000；科学模型单次最大输出 16,384。容量是实际上下文预算，不意味着每次都填满。

`parallel_topics` 限制同时执行的专题数，`concurrency.model_requests` 限制实际模型请求并发。实际 HTTP 尝试及重试计入运行账本，嵌入请求单独计数。主审预留正式评价和综合的资源；同次运行的追问与作者交接沿用累计消费。

`external_research_enabled: false` 时只使用已提供材料。`formal_review_enabled` 当前为 `false`。`english_enabled` 当前为 `true`，只需中文时在 `reporting.yaml` 中关闭。

## 输出与验证

| 路径 | 内容 |
|---|---|
| `review.json` | 准入、动态研究、评价、交付及技术状态 |
| `report.zh.md`、`appendix.md` | 中文主报告、选定附录 |
| `report.en.md` | 开启且完成相应翻译时的英文主报告 |
| `sources/` | 原始资料及取得的文本、图像 |
| `v5/sessions/`、`v5/notes/`、`v5/inquiries/` | 作者状态、不可变稿件、稳定科学问题 |
| `v5/source-readings/`、`v5/topics/`、`v5/chiefs/` | 来源阅读、专题与主审记录 |
| `v5/assessments/`、`v5/publications/`、`v5/delivery.json` | 正式评价、冻结出版材料与交付状态 |
| `v5/budget.json`、`metrics.json` | 累计实际请求消耗、并发与耗时 |

离线测试覆盖实际协议、原文与图像传递、异步协作、版本冻结、计分和报告装配。局部工具位于 `scripts/` 和 `examples/`，真实调用需显式选择相应入口。离线接线通过只能证明程序行为；材料解释、科学外推和最终判断的质量仍需通过真实运行结果评价。
