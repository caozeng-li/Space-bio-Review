# Change 33: 全局有序题单的截取与确定性派工

状态：实现及局部派工验证完成；生成质量结论见 Change 36。前置：[Change 32](change-32-single-model-question-generation.md)。

## 目标

模型负责问题内容、边界、全局重要性顺序及专家归属。代码只保存完整题单、取前 N 项、建立研究任务，不做语义合并、排序重估、补充责任或二次分配。

默认一题一位专家、一项正式研究任务。保留专家在题内检索、委派资料研究、读原文和形成论证的既有能力。题数上限控制的是正式评审题目，不等于整个项目只会产生 N 次 API 请求。

## 配置与顺序

- 在 `V4Config` / `config/review.yaml` 增加一个全局 `max_questions`，默认 10，允许配置为任意正整数。本轮不新增每专家配额、每维度配额或动态题数估算器。
- 这是可调整的执行规模默认值，不表示十题足以评完所有项目。生成提示词、schema、模型输入和生成身份均不包含它。
- 完整模型数组记作 `all_questions`；入选列表严格为 `all_questions[:max_questions]`。不足 N 项就全部入选，不补齐。
- 数组原顺序保留为程序的 `source_rank`。不得按 `expert_id`、题号字符串、维度覆盖或文本评分重排。
- 调度按原始重要性序位启动；删除现有 `research()` 为优先覆盖维度而重新排序的逻辑。允许既有并发，完成时间不必与重要性顺序一致。
- 题数限制之外的模型调用、token、时间与完成阶段预留预算继续生效。预算不足表示未完成或等待，不把后面的便宜题换进来。

## 单一问题与任务表示

完整生成结果作为不可变 `question-batch` 产物保存。程序按原始序位分配题号，包括未入选部分；同一批次改变 N 不改变已有题号。批次引用与序位是身份依据，不用题目字符串哈希做语义去重。

正式运行状态只为入选题建立可执行任务，另保存批次引用、截取设置及完整/入选数量。未入选题仍在原始批次中，但不建立 `withdraw/defer/merged_into` 等伪科学处置。

每个入选题只保存一份规范的题目内容、一个 `expert_id`、一个 `source_rank`，以及现有研究状态和产物头引用。删除根问题、合并图、共同工作组、重复维护的多成员归属和相邻题依赖图。专家身份只取自生成时冻结的配置，不按模糊学科字符串再匹配。

为了局部修改，研究入口仍可收到其现有单成员形式：

```text
members = {question_id: canonical_question}
expert_id = canonical_question.expert_id
analysis_scope = canonical_question.scope
```

这是调用 `Research.run()` 时生成的投影，不是另一份需要维护的分配模型，也不是保留旧图的兼容层。正式研究的 `scope_outcomes` 继续绑定这一个题目，证据、论述和引用身份不重写。

新题目没有 `resolution_type`、`expertise_needed`、`external_needs` 等重复的初始调度判断。调整研究输入中对这些旧字段的直接依赖，不为满足旧代码而编造默认“科学结论”。`information_route` 继续提供当前可研究路径；未决事实由实际评审形成。

## 截取结果与实际覆盖

- 单独记录题单批次、N、入选题号、原始序位和截取数量，供复现与局部测试使用。
- 不把未入选题判为“不成立”“不适用”“没有专家能力”或“已完成”。
- 维度仍从题目 `aspects` 和真实研究产物构建覆盖视图，不反过来补题。某维度有生成题可认定本轮有相关评审对象；没有题不能自动推导该维度不适用。
- 未入选题涉及的范围不能计为已评。覆盖投影需同时表达入选题的完成状态和因截取未分析的范围；不能因为入选题都完成就宣称所有相关问题已解决。
- 技术截取信息留在运行记录；给综合/报告的视图说明具体未评范围，不塞入内部队列、题号映射和派工过程。沿用公开内容与内部记录分离的已有接口，不重做报告模块。

这里不保证每位激活专家都有任务。重要性排序和全局截取可能使某位专家没有入选问题，这是透明的规模选择，不触发凑题或重新组队。

## 上下文与开销

每个正式专家只获得项目结构、自己的配置、本题完整内容及其原文定位。保留按需读取完整计划书和检索能力；不把完整题单、其他专家题目、被截取部分、全局分配表或累计未决事项塞给每项研究。

复用 `Research`、`ApplicationReader` 和既有原文缓存。删除对 `expert.orientation.evidence` 的来源收集依赖；问题来源统一来自本批生成绑定与项目原材料，不另造 E/R 身份。

在模型上下文中避免同时展开同一题的 proposal、副本 members 和同文 scope。必要的单成员身份保留，科学正文只提供一次。程序侧投影可以有接口字段，不代表模型侧要重复相同文本。

不增加共享研究组、跨题结论等待、后台共同检索规划或语义缓存。本轮优先减少重复题和重复上下文，而非引入另一套跨题协调状态。

## 实施范围

- `src/spacebio_review/v4/config.py`、`config/review.yaml`：全局截取配置。
- 新问题批次到任务的纯转换函数：接收完整题单与 N，返回有序入选任务及截取元数据。
- `src/spacebio_review/v4/coordinator.py`：任务派发、结果头、覆盖视图使用单题单专家关系。
- `src/spacebio_review/v4/research.py`：最小输入适配、移除定位证据依赖和旧调度提示。
- `src/spacebio_review/v4/publication_input.py`：必要的专家/题目目录投影，避免要求旧合并关系；不改正文和引用渲染。

## 离线验证

- [x] 同一完整题单分别取 N=1、3、大于题数，精确验证前缀、顺序、身份和专家归属。
- [x] N 不影响问题生成 messages、schema 或生成身份；只影响选择与派工身份。
- [x] 一题恰好产生一项正式专家任务，不因多维度标签重复派发。
- [x] 不足 N 不补齐；某位专家没有题不调用补题；原样输出重复题时也不偷偷去重，该情况留给生成质量验收揭示。
- [x] 并发情况下按重要性顺序准入，覆盖标签不重新排序；按数值序位处理 q2/q10 等情况。
- [x] 预算停止时保留已入选题的真实状态，不转用尾部题或重做模型分配。
- [x] 记录型 `Research` 收到本题、正确专家和完整条件；相同运行恢复不重复派发。
- [x] 完整题单很长而 N 很小时，单题上下文不随全题单线性复制。
- [x] 未入选题和未完成题均不被覆盖视图误记为已评；报告输入不含内部截取解释串。

本步不调用真实专家或检索，不用完整评审验证派工；真实生成结果的派工回放在 Change 36 中离线完成。
