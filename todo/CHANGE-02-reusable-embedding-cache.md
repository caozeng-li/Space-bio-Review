# Change 02：让内容向量跨运行复用

状态：已实施，局部与跨进程真实缓存验收通过（2026-10-08）。依赖 change 01，之后实施 change 03。

## 要解决什么

`VectorIndex` 已有内容哈希和进程内缓存；mytest16 的同文同问重复检索不会再次编码。缺口是重新创建运行后不能复用向量，以及当前一大组文本全部嵌入成功后才写入缓存，中途失败可能丢掉已成功批次的复用机会。

本 change 减少重复运行、恢复运行的准备成本，不应被宣传为能消除首次运行的全部向量请求。

PaperQA 的参考点是保存可复用的文献索引、只为缺失向量补算：[缺失向量处理](https://github.com/Future-House/paper-qa/blob/57e89f7223b0960d5ee5ea048c69e3c47e088572/src/paperqa/docs.py#L437-L454)、[目录索引保存](https://github.com/Future-House/paper-qa/blob/57e89f7223b0960d5ee5ea048c69e3c47e088572/src/paperqa/agents/search.py)。本项目只需要内容向量缓存，不需要引入数据库或复制 PaperQA 的文献系统。

## 设计决定

### 1. 延用已有内容哈希，增加磁盘层

- `VectorIndex` 接受可选缓存目录；先查内存，再查该目录，只有缺失文本请求 embedding。
- 哈希继续包含模型名、endpoint、维度、长文本分块参数、编码算法版本与规范化后的实际文本；更改其中任一项自然不复用旧向量。
- 缓存文件只保存向量，不保存文章全文、模型意见、阅读记录或凭证；同一数值结果不需要独立的业务 ID 和状态字段。
- 每个哈希一个 JSON 文件，用临时文件和原子替换写入。读入时复用现有维度、有限数值等向量检查；坏文件按缓存未命中重算，不增加巡检程序或全局缓存清理任务。
- 存储失败时本次已得到的内存向量仍可使用，留一条日志即可；缓存是优化，不应成为研究失败的新入口。

### 2. 成功一批保存一批

- `VectorIndex.vectors()` 按已有 embedding 批大小提交缺失文本，每成功一批就放进内存并写磁盘。
- `DashScopeEmbedding.embed()` 仍负责真实请求、重试、向量响应检查和账本记录；不要复制 provider 逻辑。
- 一次向 `embed()` 传入不超过现有批大小的文本即可，不需要新增回调协议。后续批次失败，不抹掉此前批次的结果。
- 保留进程内现有锁，避免同进程并发重复计算。跨进程允许少量重复请求，由原子写防止半文件；暂不实现文件锁、缓存租约或后台服务。
- 命中缓存不消耗 provider 调用额度；发生实际请求才记账。缓存命中计数只用于局部观察，不做第二套持久化预算。

### 3. 项目级路径，任务级证据仍隔离

- 只新增一个可选工程配置 `embedding.cache_dir`。`config/runtime.yaml` 建议设为 `../runs/.cache/embeddings`，由模型配置加载器按配置文件目录解析；`runs/` 已被 Git 忽略。
- 未配置目录的库调用与单元测试仍可纯内存运行。测试使用临时缓存；真实局部探针使用独立探针缓存，避免冷热对比相互污染。
- 缓存仅复用向量。各会话依然必须取得当前材料、满足可见性/截止日期要求，并实际返回原段落，才能建立证据引用。缓存中有某文本不意味着模型读过它。
- 不把旧运行文件搬到缓存，不自动修改 mytest16，不扫描其他项目的文献目录。

## 局部验收

新建 `tests_current/test_embedding_cache.py`，只运行该文件及与 change 01 直接相关的指定测试。

1. 同一文本、模型与配置：第二个全新实例/进程读取缓存，零次 provider 调用，向量与排序相同；改文本或改变模型/维度/编码版本则重新计算。
2. 并发两个查询共享文献文本，进程内相同缺失文本只编码一次。查询不同只补算新查询。
3. 构造第二批失败：第一批缓存仍在，新实例重试只处理缺失批次；预算中的真实失败尝试仍有记录，不能因没拿到向量而消失。
4. 截断文件、错误维度及不可写目录只影响缓存命中/保存，不能产生错误检索结果或使已成功取得的向量不可用。
5. 两个会话共享向量缓存，其中一个未取得/未读文献：它的证据范围不能因为缓存命中而扩大。
6. 可复用 change 01 的真实检索探针：先冷缓存，关闭进程，再以相同材料与查询运行一次；第二次 embedding 请求为零。重排模型仍可能调用，不能把“零 embedding”写成“零模型请求”。

## 完成标准与边界

跨运行复用有效，成功批次可保留，缓存不改变证据内容和任务可见性。输出只需说明命中数和真实请求数，不新增缓存状态机或版本迁移体系。

本次不做 TTL、淘汰算法、数据库、跨机器共享或自动预热；缓存可人工删除并重建。模型供应商在同名模型下无通知改变向量空间的问题不能由现有哈希完全识别，有需要时清理缓存或提升编码版本，不为此搭建模型注册系统。
