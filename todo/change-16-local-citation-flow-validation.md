## 验证目标

分别回答三个问题，不能用其中一个代替另外两个：

1. 程序是否忠实保留局部证据、论述身份、条件、推理前提和沿袭关系？
2. 在固定小范围材料上，模型是否形成并选择了语义合适的论述，而非只提交合法编号？
3. 同等必要信息下，总输入、输出和请求数是否受控，是否避免了重复发送祖先档案？

本项不是上线后的逐句校验器，也不新增生产重试。真实 API 只用来验证目标环节；没有任何样例需要启动完整评审流程。

表中的次数是独立样本数，不是重试次数。实际一次样本可能包含接口所需的多个请求或读回，全部计入累计上限，不能只把最终生成算作调用。不要为了凑齐样例而简化成未走生产契约的假流程。

## 调用边界与预算

- Change 12–16 本轮合计最多 **20 次真实模型请求，200,000 输入 token、50,000 输出 token**，任一上限达到即结束本轮调用。它们是实验支出上限，不是生产上下文阈值或必须花完的额度。
- 网络层重试、工具回合、协议能力探针和专业正式选择调用同样计入；输出中的 reasoning 按 provider 实际口径记录，不能重复计算。
- 先完成不花 API 的测试。若请求预览已显示无法在预算内完成，应先调整实际必要的工作视图，不能截断主张的条件和反证；仍不足则报告未完成部分，不自行增加预算。
- 冻结材料下的重复样本不复用模型响应缓存；材料解析、证据读取等确定性缓存可以复用。记录两者的区别。
- 不增加线上 repair 次数；诊断探针关闭语义失败后的自动改写/格式补救，已有网络传输重试若发生必须留痕。
- 研究、综合、路由和翻译使用现有对应路由。仅专业正式环节可使用此前获授权且经过能力验证的托管路由，不扩大授权范围。

同条件重复用于观察分布，必须保留所有结果，不能反复生成直到成功或只选择最好的一次。如果请求本身选错材料或协议配置错误，先修正夹具并明确记录前一批不可比较；前一批的费用仍算本轮开销。

## 结果观察

### 程序流转

看局部 E、C 身份、条件、前提和来源定位，不只看编号存在。添加背景、变更分组、增加祖先层数不应改变当前直接依据。

### 认识质量

逐个样例核对：主张对象、条件、时点、申请自述/外部认识/推断性质，及每个引用在当前位置的作用。多来源共同支持允许存在，不要求每条来源单独证明整段，也不通过来源数量判优。

区分失败起点：首次理解错误、综合改写错误、论述选择错误、保存/投影丢失、交付错误或翻译错误。上游已经理解错的样本不能用于宣称下游结构失效，也不能因下游忠实保留错误而认定内容合格。

### 开销

对同一冻结样例、同一必要信息集合和同一路由比较：实际请求总数、输入/输出合计、首轮和读回分项、目录/论述/原文/schema 大小。旧提示词可离线重建估算输入，无需额外调用旧模型来制造对照；真实计费和估算值明确分栏。

至少包含一个归档很大但当前工作很小的样例。若省下原文却新增了大量逐项请求，或者 schema 膨胀抵消节省，应如实判定没有实现该项开销目标。

## 启用与完成结论

分别报告“程序实现完成”“局部真实行为已验证”“尚未验证范围”，不写一个笼统的全部完成。

- Change 12 的确定性交付修正，经旧格式与新格式离线回放确认后，可用于新生成的交付，不依赖更换专业模型。
- 新 C 归档和新综合路径必须有往返测试及相应真实样例证据，不能仅因 schema 合法就启用。
- 在固定重复样例中仍出现影响结论的条件丢失或错误直接引用时，保留显式试验入口，说明失败来自哪里；不靠追加重试达成启用条件。
- 此前专业 `inherited` 的首次理解问题必须按本轮相关样例单独报告；综合和渲染通过不能替它证明通过。
- 不默认切换全部专业模型或全流程协议，不将专业正式环节的托管授权扩展给其他角色。确需改变默认行为时，实施结果应列明已验证的具体范围与仍存限制。
- 本轮不跑整轮评审，因此不声称已证明全项目质量、全流程成功率或整轮 token 降幅。局部稳定也不是模型永不出错的保证。

最终目标是让错误关系在正常构造和流转中不被制造，让必要上下文随当前认识而不是档案规模增长；不是在旧的混合表示末尾再加一层审查。
