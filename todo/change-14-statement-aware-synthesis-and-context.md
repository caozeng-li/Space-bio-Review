## 当前问题

[Synthesis.generate](D:/master/SpaceBioReview/demo_11/src/spacebio_review/v4/synthesis.py:208) 仍生成自由正文与 E/R 引用，尚未以 C 为复用单位。`fits/split` 主要根据模型容量切分完整块，解决的是“能否塞入”，不是“该环节需要哪些内容”。

[TaskContext](D:/master/SpaceBioReview/demo_11/src/spacebio_review/v4/context.py) 既处理工作视图又处理旧产物投影；完整 R 的正文、共同范围和来源可能反复出现在不同位置。[补研路由](D:/master/SpaceBioReview/demo_11/src/spacebio_review/v4/preparation.py:318) 也携带大批完整结果，仅在超容量时拆分。

目标是让综合对既有论述做明确的复用、比较和推断，输入规模主要由当前任务相关认识决定，而不是由祖先档案总量决定。不是再增加一道综合后核查。

## 输出职责

### 复用既有认识

模型选择已有 C。程序继承正文、条件、性质和引用，允许安排顺序和章节，不让模型为“复用”重新抄写一遍。完整继承范围内不增加模型调用。

### 形成新判断

综合不是只能拼接旧句。比较专家分歧、权衡证据、形成条件和替代方案时，可以创建新 C：

- 写清新判断及其适用范围，选择实际使用的前提 C。
- 对独立新增的材料事实选择已读 E；前提引用不自动变为直接 E。
- 判断性质保持为推断、建议或未知。申请年度计划不能因综合时间已过去而升级成已完成事实。
- 如要把旧的不透明论述细化成更精确事实，应按需回读相关材料；不能仅根据 R 的存在推定新事实成立。

采用“复用现有论述 / 新建论述”两种选择即可，不增加评分、置信度、逐句审核理由等重复字段。

### 文档组织

方面综合和总体综合使用同一论述表示。`conditions`、`options`、`unresolved` 和对外展示的后续问题也引用或包含同样的论述单位，不能只修 `blocks` 后让其余文本继续使用混合引用。

`recommendation`、条件时机、成员状态等执行字段保持原职责；不要把整个协调状态机迁移成论述图。

## 按职责投影输入

在现有论述模块内提供任务视图，不另建通用检索服务。任务视图和实际发送内容共用实现，容量预览不能看一份数据、正式调用又发另一份数据。

### 方面综合

- 初始提供该方面真实分配范围内的当前 C，以及其局部条件、必要前提、相关反证和未知。
- 相同 C 和共同范围只呈现一次；原文 E 正文不在多个 C、材料包和目录中重复展开。
- 对仍需比较但暂未展开的认识，提供紧凑目录：身份、现有标题/任务关联、性质、范围标识和可读取入口，不为目录额外调用模型生成摘要。
- 延续按问题聚合的组织方式，不能为缩短输入只保留多数意见或支持结论。

### 总体综合

- 以各方面选中的结论、决定性条件、分歧、未知及实际覆盖为工作集。
- 专业原文和内部综合保留按需访问入口，不默认重复携带每一级完整论述。
- 多级归并传递 C 身份和新形成的判断，不把前提树重新写成越来越长的块。
- 跨方面复用同一个 C 不制造多个“独立支持意见”，也不增加重复证据权重。

### 请求路由

只调整路由使用的知识视图和对外说明，不重写任务合并、派工、预算及重试策略。

- 常驻输入为待处置请求、必要工作状态、相关问题范围、已形成判断的紧凑索引。
- 优先使用现有成员/问题归属缩小候选集；保留全局索引和按需读取能力，不能依赖脆弱关键词筛掉跨问题可复用分析。
- “复用哪些工作”继续使用 R/工作关联；对外说明中的事实使用局部 E 或已选 C。两者分别交付。
- 请求多时可按问题归组分批，但只有能够减少实际输入时才拆；不得把相同的全量结果在每批再发送一次。

## 开销决策

1. 复用内容用 ID，不用再摘要；读取一个 C 时同时提供必要条件，不要求为条件额外发一次请求。
2. 原文回读只为新的理解或争议核实。已有证据身份目录不是必须重新通读所有原文的任务清单。
3. 限额继承现有任务及共享预算。按需读取占原有额度，不新增无限读回或“直到通过”的循环。
4. 如果完整的必要认识仍超过容量，沿用现有有界归并方式，但归并输入和输出均为 C 集合；不能任意截断论述、条件或反证。
5. 分别记录目录、论述、原文、公共范围、schema 和总输入的大小，以及回读成本。最终比较总成本，不只比较首轮提示词。
6. 默认不为每条 C 单独调用模型。一次局部综合可以复用多条 C 并形成必要的新判断。

## 接入与兼容

沿用既有协议选择和产物版本，不为每个字段增加运行开关。新的综合表示通过明确的协议版本接入局部探针；旧输入通过 Change 13 的适配器读取。新旧表示的真实语义不同，缓存身份必须包含对应版本和输入身份。

专业阶段目前的 `inherited` 仍是显式选择，不能假定 mytest19 已启用。也不能直接给现有 `research_contract` 加一个布尔参数就宣称综合完成迁移：当前编译器、方面输出、条件、后续问题都需要对应接入。

默认模型和托管授权不扩大。用户已有授权仅覆盖专业正式提交；研究、综合、路由、翻译仍走各自现有路由。
