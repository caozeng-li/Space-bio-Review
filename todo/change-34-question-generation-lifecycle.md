# Change 34: 问题生成提交、生效与恢复

状态：实现及离线恢复验证完成。前置：[Change 32](change-32-single-model-question-generation.md)、[Change 33](change-33-ranked-question-dispatch.md)。

## 目标与依据

mytest22 的 `prepare/allocate/initial` 在保存模型产物后已标 `committed`，但 `apply_plan()` 在 `execute()` 外部失败；状态没有记录同一任务的应用失败，恢复还会拿到同一份错误计划。这是提交含义与状态生效脱节，不是缺少一次模型校验。

新流程不再有语义合并编译，但“拿到响应”和“研究题单已生效”仍不能混同。本步只收口问题准备操作，不重写所有 Agent 的事务或增加通用工作流框架。

## 一次生成，两种明确产物

1. `question-batch`：完整、已解析的模型有序题单，附真实原响应收据和来源绑定。
2. `question-selection`：对该批次按 N 选择并形成的研究任务，与对应运行状态一起生效。

只保存第一项，不能代表任务已经派分。成功标记必须和入选题、任务、批次引用、截取设置一起在既有原子 `save_state()` 中落盘。中途失败不能留下部分入选任务或假 `committed`。

用小范围的准备操作实现这条顺序，复用 `Records.put/receipt/save_state`。不用完整的旧 `planning_coordinator`，也不把工作组编译器包装成新题单提交器。

## 响应保存与恢复

复用上一轮 `PlanningSubmission` 已实现的可用部分：原始响应在解析前保存，正式 source mapping 随收据保存，恢复可按原契约本地解析。去掉 read_context/restore_reading 等本轮已不存在的业务分支。通用 Adapter 与 recorder 保留，不复制另一套 HTTP 客户端。

最小恢复语义：

| 已知事实 | 恢复行为 |
|---|---|
| 请求确定尚未发送 | 继续待执行，不计作已消费的生成 |
| 已发送但未留下可确认结果 | 报告结果未知，不自动再次付费生成 |
| 原始完整响应已保存但未解析 | 用冻结契约和来源映射本地解析，不调用模型 |
| 完整批次已保存但选择未生效 | 重新执行确定性截取与状态生效，不调用模型 |
| 题单已生效 | 继续未完成研究，不重新出题或派发已完成任务 |
| 响应截断或字段解析失败 | 保存原始失败与 usage；不续写、不用前半份题单、不自动重抽 |
| 程序投影或落盘失败 | 同一准备操作记录失败，保留已取得批次，供修正代码后本地继续 |

这些是操作本身的生命周期，不是多轮校验。显式重新生成属于新的尝试，必须有明确操作入口和独立费用记录；普通 resume 不代表授权重抽。

## 身份范围

生成身份只包括实际科学输入、激活专家投影、提示词/契约和实际使用的生成路由配置。不能纳入 `max_questions`、无关 writer 参数或完整运行预算，使一个纯执行设置变化触发再次生成。

选择身份包括生成批次引用、N 和确定性投影版本。未生效前改变 N 可直接重算选择，不重新调用模型。

已生效运行冻结题单与 N；恢复时若用户改变它们，明确要求新输出目录，不偷偷撤销已完成研究或追加新题。本轮不做跨版本旧 checkpoint 自动迁移，也不做科学输入变更后的在线题目重排。

项目读取、项目映射、组队、问题生成分别有可恢复产物。只因最后出题失败，不应重新支付所有前置步骤；不得通过重新执行整个 preparation 来替代复用已完成产物。

## mytest22 其他问题的处置

| 观察到的问题 | 本轮处理 |
|---|---|
| q8 等多目标合并、q11/q14 环、成员范围与根冲突 | 随合并协议整体删除，不扩大解析容错、不猜测箭头方向 |
| 一些题只出现在他题成员列表，未独立分配 | 新模型每个数组项自带一个专家；程序从同一项建立题目和任务，不再维护两份成员名册 |
| 专业定位中的额外字段及其修复调用 | 删除专业定位阶段，相关请求与错误入口一起消失，不继续修补定位 schema |
| 保存计划即 committed，应用异常没有进入事件 | 成功状态与入选任务同次生效；同一操作捕获并记录本地应用失败 |
| 同一失败恢复重复撞上旧计划 | 原响应/批次可重放，失败与已生效有明确区别；恢复不再走旧 `apply_plan` |
| 研究尚未开始却被概括为 research failed | 问题准备失败时研究状态为 `not_run`；真正启动后失败才报告研究失败，不改科学判断 |
| 模型调用失败数为零但工作流失败 | 保留 transport 指标真实含义；从操作状态输出阶段与本地失败原因，不伪造供应商失败次数 |

对 mytest22 的科学内容、全文评审质量不作额外承诺。上一轮候选的 read_context 身份错误随旧增量规划入口退役，不另做一次局部“修复后再保留”。

## 错误输出

准备失败应在 `review.json` 的任务、阶段和 `technical_limits` 中指向实际操作及原因；没有评审正文时沿用现有未交付说明。生成成功但专家尚未运行不能输出评审结论。

不把原始 schema、内部批次 ID、收据、token 或错误恢复叙述作为科学报告输入。详细记录留在运行产物，用户交付继续沿用现有公开内容 Interface。
