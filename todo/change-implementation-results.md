### 失败原因与本地修正

1. **早期已有问题遗漏**是表达职责问题，不是 JSON 字段解析失败。intent-3 将已有问题编码为必填槽，避免模型重新列名单；旧失败不重算为成功。
2. **L3-6 截断**是实际输出容量失败。Messages 的 max_tokens 由正文和 thinking 共用，16,384 耗尽；没有证据能把全部耗用归为正文，也没有继续补写。必填槽与重复责任文本虽然保住身份，仍可能增加生成负担，这部分尚未稳定。
3. **L4-5**选了已展开的 w1-w4，导致计划出现第二次请求。不是服务端返回错误字段；是读取选项没有排除已展开对象，加上“每次直接一调用”的实验假设被打破。调用限制在发送前生效，pending 保持，未把它当作成功无新增工作。
4. **L5-4**明确属于实现错误：目录给论证产物 ID，`restore_reading` 却按论述块键查找；模型同时填两套读取字段，又放大了歧义。此前工具读取加正式 read_context，再加最终正式提交，设计上还可能需要三次请求，超过 L5 两次约定。

停止真实调用后，workspace-5 删除规划的工具读取入口，只留 `read_context.targets`；可选值只含未展开对象。程序按目录类型展开科学对象或整份论证，收据仅保存规范块键，模型不再填写 `target_ids` 与 `argument_ids` 两套命名空间。真实 L5 选中的三份产物在离线测试中全部展开，正文、条件和块内容逐项保留；真实 Runtime 配合记录型供应商验证两次正式调用完成读取与提交，重复恢复追加调用为零。**这不是 L5 新版真实通过，也不证明两次一定足够所有科学任务。**

### 实质问题

1. **仍会把未知条件填成答案。** 新版 A1 第一题写“形成 ≥10 μm 凝聚体”使观测前提成立，原文只说尺度大、稳定性强及 20 倍镜/25 帧每秒；没有这条校准门槛。A2 第五题出现“计划书内 1g 在轨对照”，原文是地面对照。它们不是字段故障，也不是测试环境模拟出来的错误。
2. **题面不同，不代表实际分析范围不重复。** A3 第二题和第五题都承担细胞设计可识别哪些因果效应、统计效能以及蛋白结果与细胞结果如何整合。第二题信息路径已经要求计算重复数，第五题再称自己负责统计，不能靠两个 scope 的排除句构成清晰分工。A2 第六题的 `changes_judgment_if` 还原样复制了第五题的地面模拟条件，已偏离本题 FFA/应激归因。
3. **地面预研与正式对照仍会被混淆。** A-small 第四题把旋转培养器、微流控的预研与按在轨流程开展的常重力对照合成一个判断，进而要求模拟结果能够预测在轨结果，否则对照基础薄弱。这改变了原方案的实验角色。
4. **少而不重复，不等于覆盖足够。** B 的五题分别处理因素拆分、操作验证、统计效能、类器官表型定义和设备来源，却没有交给任何专家判断 mtDNA 类核、ROS/钙、回收测序是否真正反映目标线粒体变化。多个 scope 显式排除这些内容。这是完整题单的遗漏，不是 N 截断；不能靠让每个专家凑一题修复。
