# V2：以持续形成结论为主线的科学项目评审 MAS

本文提出对 [V1 现有实现](v1.md) 的调整方案，尚未修改运行代码。目标是保留科学评审的思想与智能体协作价值，降低完成一次评审所需的组织复杂度、模型操作负担和串行成功依赖。

## 1. 方法主张

**初审后形成暂定结论，后续活动只用于检验、修正或限定该结论。**

结论不必等待所有问题消失。它可以是明确建议，也可以是成立条件清楚的建议、无法排除的两种判断，或有具体理由的证据不足判断。系统需要说明在现有材料下能判断什么、不能判断什么，以及这些未知如何影响建议。

降低的是程序性闭合门槛：不再要求所有专家任务、全部议题和完整分支网络都成功完成。保留的是科学底线：重要判断有依据，关键条件和反对理由不被省略，技术失败不被包装成科学证据不足。

“持续形成结论”也不意味着先定资助立场再寻找支持。首个暂定结论在专家独立初审提交后形成；后续可撤回、减弱或完全改变，且必须主动检验最强反对理由。

## 2. 保留的思想与简化的实现

| 保留的思想 | V1 的主要实现 | V2 的实现 |
|---|---|---|
| 自适应专业分工 | 显式专业需求、目标覆盖、互补功能与动态增补 | 主席生成简洁任务分工，按项目选择专家；必要时一次专项补充 |
| 专家独立判断 | 独立会话、初始草图、独立搜读与初稿 | 保留初审隔离；提交短评审意见，原文与详细依据按需回读 |
| 有依据的推断 | 项目图、论证图、原文锚点与适用范围 | 项目简报、关键判断及证据引用；重点保存推断前提 |
| 理性处理分歧 | 多轮质询、研究计划、独立修订、主席裁定及依赖重开 | 只处理影响结论的关键问题，相关专家回应后直接更新结论 |
| 条件与敏感性 | 解释集合、兼容分支、专家逐分支复核和价值取舍 | 围绕关键不确定性表达“若成立／若不成立”的建议变化 |
| 独立元评审 | 独立读申请，再对完整正式结构复核并路由返工 | 保留隔离阅读与最终质疑，只允许一次聚焦修正 |
| 读者可用的报告 | 独立双语写作、语义核对与局部修订 | 保留，输入改为简洁结论底稿及关键依据 |

不以增加对象、图和调用数量证明 MAS 的完整性。完整性体现在能组织互补判断、检验重要异议，并产生与证据相称的评审结果。

## 3. 智能体架构

### 3.1 主席：结论的持续维护者

主席承担项目简报、专家分工、暂定结论、关键问题选择和最终综合。它不再分别完成全量项目图修订裁定、全量论证关系建图及完整解释分支规划。

主席每次更新结论，只需回答：

1. 当前建议是什么，最主要的依据是什么？
2. 哪个反对理由最可能使建议不成立？
3. 哪项未知可能改变建议类别、接受条件或可支持的主张范围？
4. 当前是否存在值得执行的核查，还是应该直接保留条件或不足？

主席不能通过删掉异议来宣布稳定。专家原始意见独立保留，元评审可直接回读，不以主席摘要作为唯一依据。

### 3.2 专家：少量互补任务，集中科学判断

默认由主席安排三位专家，分别覆盖项目的重要认知任务；具体专业和职责随申请变化，而非固定三种角色。确需额外覆盖时可安排第四位。

专家初审提交总体判断、主要理由、重要缺口和建议条件。默认突出三至五项关键判断，属于表达优先级，不以条数截断额外的决定性异议；其余内容可归并为次要意见。

初审后仅相关专家参加某一问题的复核。它们不重写整份初审，也不负责操作全局图；只说明新材料是否改变原判断、怎样改变，以及当前仍成立的理由。

### 3.3 证据研究员：完成可影响判断的具体调查

保留独立研究角色与现有外部文献能力。初审专家可直接搜读，复杂查证可委派研究员；同一问题的公共补证优先由一个调查任务完成，结果交给相关专家分别解释。

每次补证明确问题和预期影响，例如“若有匹配证据，是否足以支持样本保存后仍可完成形态学测量”。不再把“还有相关文献可搜”当作继续研究的充分理由。

初审使用各自独立的证据解释；讨论阶段可共享正式证据包。共享原文缓存不等于提前共享其他专家立场。

### 3.4 元评审：独立质疑而非另一个委员会

保留先独立阅读、后接触结论的两阶段信息隔离。独立阅读可与专家初审并行，形成简短的问题清单；不要求另一套完整项目模型和意见网络。

最后检查暂定结论是否遗漏重要异议、混淆科学标准、夸大证据或忽略可能改变建议的条件。只反馈实质影响结论的问题，允许一次聚焦修正，不发起无边界的新议程。

元评审提出新科学主张时，应给出依据或回到相关专家作一次回应。最终仍不能解决的分歧留在结论中；不能因为元评审身份而自动采纳其新判断。

### 3.5 撰写者：将结论交付给读者

保留 Synthesizer 和独立双语语义核对。输入包括当前结论、必需保留的条件和异议、关键证据及必要原始意见。代码负责引用和文件组织，模型负责论述。

写作不重新开展科学评审。写作失败不删除已经形成的科学结论；结构化结果与简洁结果页仍可导出，未通过语义核对的双语文本不标为正式完成报告。

## 4. 核心工作对象

跨角色协作收敛为四类内容；来源存储和私有工作记忆继续作为底层能力存在。

| 对象 | 内容 | 用途 |
|---|---|---|
| 项目简报 | 目标、拟支持的主张、基本方案、主要实施前提、申请出处 | 建立共同任务理解，代替默认构建完整项目图 |
| 专家意见 | 判断、理由、证据、成立前提、重要异议、建议条件 | 保存独立认知贡献 |
| 当前结论 | 暂定建议、决定性理由、接受条件、重要分歧、未知与敏感性 | 始终存在的综合底稿 |
| 关键问题 | 可能改变结论的具体问题、相关专家、核查方式及处置 | 约束后续工作与更新结论 |

专家意见不再拆成必须维护全量关系的公共论证图。结论仍可引用某位专家的某项判断，代码生成简单编号，模型从可见列表选择。证据只需保存一份，其他对象引用它，避免在多个任务包中反复复制全文。

项目依赖思想保留在关键判断中，例如“保存质量影响可测量性，可测量性影响可支持的科学主张”。仅在它确实改变评审意见时显式表达，不要求为全部节点和边建模、修订和传播。

## 5. 主流程：先形成，再检验，再收束

### 步骤一：准入、简报与分工

复用现有解析与准入能力。主席在一个简洁任务内形成项目简报和专家任务，保留原申请回读入口。此时不提出委员会整体资助建议。

### 步骤二：独立初审与独立问题清单

专家并行初审；元评审独立阅读申请，暂不查看专家意见。完成的有效意见可以进入后续综合，不因为一个非关键专家任务失败而全部作废。

若缺失的专业判断关系到核心主张，主席必须明确这一缺口，优先一次补充或降低结论可支持的范围。若连基本评判依据都没有形成，则报告评审未完成，不能硬造建议。

### 步骤三：形成首个暂定结论

主席读取有效初审，形成当前结论，区分贡献、可行性、关键条件和最强反对理由，同时选择少量值得处理的关键问题。此处已经形成可读的科学评审底稿，不等待全部讨论结束。

首个结论即便是“现有材料不足以支持核心机制主张，但足以评估方法探索价值”，也应明确分别支持哪些判断以及依据。

### 步骤四：围绕结论开展有限复核

每个选定问题只走必要路径：

- 已有材料足够：相关专家直接回应，不额外检索。
- 存在具体可查事实：一次定向补证，再交相关专家回应。
- 存在关键专业缺口：一次专项专家补充，不扩充整套委员会议程。
- 属于评价取舍：主席结合共同评价语境说明选择，保留合理异议。

同批专家回应相互隔离，避免先返回者影响后返回者。完成后主席更新当前结论，并说明更新依据；不要求各专家同时成功重写整份 Opinion 才能吸收有效回应。

默认处理至多三个优先问题，最多两轮结论更新。未选问题仍在底稿中标明其影响：若它可能推翻结论但未被核查，就不能声称建议稳定。额外调查必须在既定轮次内替换优先级较低的工作，不能无限追加。

### 步骤五：独立复核与最终收束

元评审用自己的独立问题清单，对照当前结论和原始专家意见，提出需要修正的实质问题。主席可直接修正表达或取舍；需要科学回应时，只向相关专家进行一次定向核查，纳入整体收束额度。

最终允许留下未解决分歧。若争议足以改变建议而没有依据取舍，则形成分歧性或证据不足结论；不能为通过检查而强行统一。元评审已经指出的问题必须有明确处置，但不要求它最终表示赞同。

### 步骤六：双语交付

将当前结论确定为科学结果，再生成中文、英文报告并核对。科学结果、独立复核状态、文档交付状态分别表达，不用一个成功标记掩盖差异。

## 6. 怎样决定继续工作

继续调查或讨论需同时满足两个条件：

**该问题可能实质改变当前结论，而且本轮存在有希望澄清它的具体行动。**

“实质改变”包括建议类别变化、决定性条件变化、可支持的主张范围变化，以及重要反对理由能否成立。它不只指从支持变成反对。正面价值的遗漏同样可能改变结论，议程不能只挑风险与缺陷。

主席以自然语言说明选择理由，不为此再引入一个打分模型或精确的信息增益算法。代码只管理有限问题槽、轮次和任务预算。

对暂时无法澄清的事项，按其意义表达：可以后续验证且不否定当前阶段价值的，转为明确条件；决定核心主张成立与否的，保留核心不足或分歧；一般改进建议直接进入报告。不能把缺失的决定性证据统一改写成“附条件支持”。

## 7. 闭合门槛

科学评审可闭合需满足：

1. 已有可用的申请理解与专业判断，足以说明结论所覆盖的范围。
2. 主要理由、重要异议和成立条件已有明确表达及可回读依据。
3. 可能改变建议的已知未知，已被解决，或明确反映在建议的条件、范围、分歧或不足中。
4. 下一步没有值得在本轮继续执行的关键行动，或预定的聚焦复核已结束。

这不要求所有专业问题有答案，也不要求所有专家同意。建议稳定意味着在已识别的重要替代解释下不发生实质变化，而不是已穷尽所有可能性。

技术完成与科学判断分开处理：

| 情况 | 处置 |
|---|---|
| 调查正常完成但没有足够证据 | 可形成有依据的证据不足判断 |
| 专家对证据有两种合理解释 | 保留双方理由及对应建议，不强制统一 |
| 一个非关键补充任务失败 | 保留已有有效结果，标明核查缺失，不否决整轮 |
| 关键判断所需任务失败 | 限定相应结论；无足够评判基础时标明该部分未完成 |
| 独立复核服务失败 | 保留科学综合，明确“未完成独立复核”，不能标为已复核 |
| 撰写或翻译失败 | 保留结构化科学结果，分别标明文档未完成 |
| 模型服务整体不可用 | 结束新模型调用，导出已有有效成果与未完成范围 |

新反证若击中当前结论的关键前提，必须立即将相关判断标为待修正或不再成立；即使随后修订任务失败，也不能原样发布已经被反证动摇的旧建议。保留产物不等于保留其有效性。

## 8. 降低 LLM 的操作负担

### 小对象整体提交，大内容按科学单元提交

短专家意见、单个问题回应和结论更新采用小型结构化输出。必要的长内容按完整的科学判断或报告章节拆分，不按每条边、每个引用关系和每个修改步骤拆成工具动作。

模型主要完成“读材料—判断—解释”，代码承担编号生成、引用解析、来源映射和对象装配。对正文中的科学含义仍由角色和元评审核对，代码不尝试以大量形式约束替代科学判断。

### 回应问题，不编辑全局对象

复核任务只提交：问题标识、回应、依据、是否改变判断、修正后的表述和剩余条件。程序将回应关联到原意见，主席决定对整体结论的影响。模型不再同时操作正式论点 ID、私有草稿句柄、替换对象和图关系。

### 上下文按任务选择

专家初审读取申请与本人分工；问题复核读取该问题、本人相关意见、必要的对立理由与证据；主席默认读取短意见与当前结论；元评审拥有原始意见和来源回读能力。

关键前提、原文引用与重要异议不可只保留在自由摘要中。它们作为独立可回读内容保留，默认任务包避免重复携带整套历史。代码侧的上下文装配优先于要求模型自行压缩巨大的固定输入。

### 有限纠错，及时交付

保留基本字段、已知引用和来源存在性检查。格式错误有限修复；局部任务失败后，不启动同复杂度的完整重做链条。可用成果按其实际覆盖范围进入结论，缺失部分明确保留。

## 9. 条件推理的简化

默认不构造全部解释组合，也不要求所有专家逐一检查分支。

对真正影响结论的前提，直接记录：前提是什么；现有证据如何；若成立，建议及其理由是什么；若不成立，建议及其理由如何变化。只有多个前提存在明显相互制约时，才由相关专家检查少量有实际意义的组合。

相互依赖的条件不能被当成各自独立成立，未核查的关键组合要保留为不确定性。保留 V1 的敏感性思想，但不将完整分支覆盖设为每份申请的必经门槛。

## 10. 空间生命科学例子

以“在轨固定细胞样本，经保存后返回地面成像，评估空间环境相关形态变化”为例。以下用于说明调度，不代表对真实项目的科学结论。

三位专家分别检查实验对照与因果识别、保存与成像测量、在轨操作与科学贡献。初审后主席形成暂定判断：项目可能具有流程探索价值；对空间环境机制的解释需要匹配对照，保存后成像是否可用则受具体条件影响。

主席选择两个可能改变建议的问题：保存条件是否支持目标测量；现有对照是否足以支持申请承诺的归因。

保存问题交给研究员做一次匹配对象、固定方式和时间条件的调查。若只得到间接文献，测量专家可把可支持的结论限定为需要预验证的流程可行性，不能把其他对象上的结果直接外推。

归因问题若申请本身已明确缺少关键对照，就直接由相关专家说明可以支持到什么程度，无需为了“完成讨论”继续检索。若对照缺失使核心目标无法回答，应降低或否定对该目标的支持，而不是自动转为附条件支持。

最后按评价语境区分两种情形：若流程探索本身具有足够价值，可提出范围受限的建议及必要验证条件；若申请的主要价值依赖无法支持的机制主张，则应修改后再评或作其他与证据相称的建议。任务价值专家的积极理由与因果专家的反对理由可以同时保留。

这次评审的结束点是两类科学价值和关键限制已经表达清楚，不是把保存科学与空间机制的所有问题研究完。

## 11. 代码调整方向

| 现有部分 | 处理方式 |
|---|---|
| DashScope 适配、解析、准入、Skills、外部文献与来源保存 | 复用 |
| AgentRuntime、上下文与结构化生成 | 复用底座，简化角色提交接口及任务包 |
| 组委、专家独立上下文与并行执行 | 保留，分工对象改轻量 |
| 全量项目图和论证图维护 | 从默认主链移除，保留关键前提、判断及必要关系 |
| 多阶段议题循环、依赖重开与专家反复增补 | 替换为围绕当前结论的有限问题复核 |
| 完整 BranchPlan 与逐分支专家检查 | 替换为关键条件敏感性说明和按需组合检查 |
| 两阶段独立元评审 | 保留信息隔离，缩短产物与反馈链条 |
| Synthesizer 与双语语义核对 | 保留，适配新的结论底稿 |
| 最终全成功门槛 | 改为结论内容足以交付，独立表达核查与技术完成范围 |

编排仍可使用 LangGraph，但只表达简洁主阶段；框架不承担科学判断。暂定结论在形成和更新后保存为普通正式产物，最终导出不依赖再调用一个模型；这不引入断点续跑或审计系统。

后续实现顺序应是：先建立轻量意见与当前结论接口并接通报告；再替换问题复核循环；最后适配元评审与失败收束。旧的复杂链条不与新链条同时保留为两套长期维护的运行模式，V1 文档承担方法对照作用。

## 12. 方案的取舍

V2 放弃默认获得完整论证网络、详尽图修订和解释组合覆盖，换取更少的上下文复制、对象操作和必须串行成功的任务。代价是关系分析的完整性下降，主席选择关键问题的影响上升。

因此保留三项制衡：初审独立完成后才形成整体立场；元评审可直接读取原始意见并检查遗漏；未核查但可能改变建议的问题必须进入结论的不确定性表达。它们比为所有材料维护完整图更直接服务于本系统的评审目标。

默认人数和轮次是控制实施规模的起点，不是已经证明最优的参数。方法是否有效仍取决于专业分工、证据理解、异议保留和结论质量，不能以“总能输出报告”替代这些要求。
