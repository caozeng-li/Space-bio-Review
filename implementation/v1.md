# V1：科学项目评审 MAS 的现有实现

本文记录调整前代码中的架构、智能体分工和方法实现，作为 V2 的对照基线。它描述实现方式，不是运行问题记录、验收结论或后续实施计划。

## 1. 方法定位

V1 将科学项目评审建模为一个由主席、互补专家、证据研究员、独立元评审和报告撰写者组成的委员会。输入为主申请、附件与共同评价语境；输出为科学建议、成立条件、重要异议、证据依据及中英文报告。

核心思想包括：

- 专业分工随申请的知识与方法需求生成，而非固定几个身份提示词。
- 专家先独立阅读、调查和判断，再接触其他专家的意见。
- 评审围绕有依据、有前提、有适用范围的论证展开，不平均专家分数。
- 意见冲突通过质询、补证和观点修订处理；合理分歧可以保留。
- 科学解释与评价取舍分别表达，条件性和分裂性结论均是允许的结构。
- 元评审独立检查遗漏、推断、异议与结论敏感性。
- 科学综合与报告表达由不同角色完成。

## 2. 架构与主要代码

外层以 LangGraph 表达阶段调度，内层以统一的异步 AgentRuntime 执行智能体的工具循环。角色拥有独立会话、工作记忆与工具会话，通过正式产物交接。

| 层次 | 实现职责 | 代码入口 |
|---|---|---|
| 全程编排 | 准入、科学评审、返工和报告路由 | [runner.py](../src/spacebio_review/runner.py) |
| 智能体运行器 | 模型调用、工具执行、上下文、Skills、提交与有限修复 | [agents/runtime.py](../src/spacebio_review/agents/runtime.py) |
| 委员会 | 项目建模、专业需求、组委、独立初审、图汇合及专家增补 | [committee/service.py](../src/spacebio_review/committee/service.py) |
| 证据研究 | 问题导向搜读、证据保存、适用性与不足回答 | [evidence/research.py](../src/spacebio_review/evidence/research.py) |
| 议题讨论 | 质询、补证、独立修订、影响传播与议题重开 | [deliberation/service.py](../src/spacebio_review/deliberation/service.py) |

技术底座为 Python、Pydantic、LangGraph、异步模型与工具接口。模型通过 DashScope 的兼容接口调用，由配置选择。评价语境及专业方法采用文件式 Skills；原文和正式结果保存到单次运行目录，没有数据库、恢复调度器或前端。

## 3. 智能体组织

### 主席与专业专家

主席先把申请转为项目模型，再推导专业需求 `ExpertiseNeed`，为专家生成 `ExpertAssignment`。分派包含研究对象、认知任务、负责目标、判断功能、互补检查与方法 Skills。专业需求覆盖与关键接口的互补判断是组委依据。

专家获得共同申请入口、主席的初始项目草图、本人任务和共同评价语境。专家可以回读原申请，直接使用文献工具，或委派证据研究员；不接触其他专家尚未公开的初审意见。每名专家提交自己的 `Opinion`，包含贡献、论证、替代解释、缺口、要求以及对项目模型的修订建议。

主席在本批初审完成后汇合正式意见，处理项目图修订，并组织论证之间的关系。讨论中出现新的专业需求时，主席可以增补专家；新增专家先完成独立初审，再获得相关讨论材料。

### 证据研究员

证据研究员接收具体问题、竞争解释、已有材料和评价语境，自主选择检索、阅读、比较与停止。它提交证据包，不代替原委派专家作最终专业判断。

发现入口包括 Europe PMC、OpenAlex 和可选 Tavily；已知网页可直接读取，动态页面按需使用 Playwright。XML、网页、PDF、DOCX 等材料解析后保留来源和定位。长材料采用 BM25 与可配置的模型重排定位相关段落，再由模型判断证据意义。

证据条目区分可获得的材料范围、实际阅读范围、原文依据、科学解释和外推限制。调查执行完成与科学支持程度分开：正式提交可以是支持、条件性支持或证据不足。

### 独立元评审

元评审分两阶段。第一阶段独立阅读申请与共同评价语境，可以自行搜读，但不接收委员会意见、双图、综合或选文目录，形成自己的问题与可能遗漏。当前调度中该任务在初审后运行，信息视图仍与委员会隔离。

第二阶段读取委员会正式产物、原始与当前意见、讨论、分支和综合，对照自己的问题，检查覆盖、相容性、结论敏感性与重要异议。它还可回读本轮来源目录与材料。反馈可要求重开议题、增补专长、修订论证或重新综合；新的否定性科学判断需进入质询，而非直接覆盖专家意见。

### Synthesizer

主席负责科学综合，Synthesizer 负责面向读者的表达。撰写者读取当前正式底稿，先确定提纲，再按节成对生成中英文；代码负责来源编号、文件与状态。独立语义核对任务检查条件、异议、外推前提和双语判断强度，允许一轮局部修订及复核。

## 4. 领域表示：项目图、论证图与解释分支

### 项目图

`ProjectGraph` 的节点表示目标、主张、设计、观测、分析和条件；边表示依赖、产生、推断和区分关系。节点与边区分申请明确陈述、解释性假设和未知事项，并保留原文锚点。

专家通过 `ProjectAmendment` 建议修改。主席逐项采用、保留争议或说明不采用理由；初始项目模型与当前采用的模型分别保留。

### 论证图

一条 `Argument` 包含判断对象、评价维度、立场、主张、依据、推理、前提、范围及替代解释。关系包括支持、攻击和前提依赖，并说明针对证据、推理、范围还是主张。

评价维度包含科学价值、创新性、严谨性、可行性及任务相关性。不同维度上的褒贬不自动解释成同一命题的赞成票和反对票。要求进一步区分决定性缺口、接受条件与改进建议。

### 解释分支与价值取舍

讨论后，主席生成 `Interpretation`，显式表达解释、假设及互斥关系，并构造兼容的 `Branch`。分支包括采用的解释、成立前提、支持与反对论证、各维度评价及相关专家。

相关专家分别检查分支前提是否科学相容。未展开的路径通过 `UncoveredPath` 保留及说明其可能改变建议的方式。通过分支检查后，主席根据共同评价语境形成 `ValueChoice` 和 `Synthesis`：结论结构为稳定、条件性或实质分裂，建议类别来自评价 Skill。

## 5. 讨论与返工

主席从项目依赖与论证中形成议程，区分知识推断、价值取舍、残余不确定性及混合议题，也检查一致但依据薄弱的路径。

每轮讨论包含以下步骤：

1. 相关专家重构已有强理由，提出针对具体论证的质询。
2. 主席决定回读、逻辑讨论、定向补证或专家增补；纯价值取舍不转成文献问题。
3. 共同证据与质询材料形成后，冻结同轮输入，各专家独立提交修订。
4. 主席处理项目修订、论证关系、未答质询及剩余解释，决定结束或继续。
5. 根据依赖方向生成影响候选，由主席判断是否需重审下游议题。

修订可以维持、限定、撤回或替换原论证，保留初稿与修改理由。议题可以结束为已解决、稳定分歧或证据受限，也可以因预算或技术原因未完成。元评审反馈可重开相关议题；返工后重新进行分支构造、科学综合与元评审。

## 6. 运行器、上下文与产物提交

AgentRuntime 将角色指令、任务、评价 Skill、专业方法、材料视图及私有记忆装配为上下文。角色可以加载方法、回读材料、记录显式笔记及使用自己的研究工具。长交互触及软预算后生成工作摘要；共享的是正式观点和可回读材料，不是其他专家的完整私有会话。

正式产物有两种路径：

- 较小对象在工具循环声明就绪后，由同一智能体生成结构化响应，并有限修复。
- Opinion、RevisionSet、Integration、BranchPlan、Synthesis、MetaReview 等长对象通过 `ProductDraft` 逐项写入私有草稿，代码生成编号和句柄，最后短确认并装配完整对象。

增量方式支持读回、修改与删除条目，避免要求一次响应重复整份长列表。未确认草稿不发布，失败修订不覆盖已有正式意见。工具、模型响应和修复均使用有限预算，证据探索预留收束动作；固定材料与会话摘要分别处理。

## 7. 全程调度与闭合条件

公开入口先解析主申请和附件，再进行最低可评审性检查。有效但科学薄弱的计划仍进入委员会；明显无关或无法辨认目标与基本方案的输入拒止。准入与委员会复用已解析材料。

当前科学主链为：

**委员会初审与汇合 → 独立元评审读申请 → 议题讨论 → 分支构造与专家复核 → 主席综合 → 元评审复核 → 必要的局部返工 → 双语报告。**

具体路由条件由 `ReviewRunner` 实现：

- 初审要求汇合有效且每位分派专家均有正式初稿，否则转入受限报告路径。
- 独立元评审未完成、讨论整体未完成或综合任务失败，转入受限报告路径。
- 分支无法形成、相容性检查否定或存在关键科学反馈时，进入返工。
- 最终元评审没有需处理的关键反馈，才将科学状态设为完成。
- 报告阶段检查委员会任务中的技术失败；存在失败时，顶层状态改为失败。
- 顶层建议仅在科学状态完成且具有正式综合时发布；报告表达状态独立记录。

讨论内部按开放议题调度。单个议题失败或到限后可以继续其他开放议题；最后结合议题状态与依赖重审情况确定讨论整体状态。

默认配置提供全局任务上限、单角色动作与响应上限、单议题及总讨论轮数上限、分支上限和返工上限。报告另在同一全局额度内预留任务槽。额度限制约束执行规模，科学闭合仍由上述阶段条件决定。

## 8. V1 的方法特征

V1 以显式领域结构和分阶段职责实现委员会：先建立项目与论证，再讨论和修订，最后构造条件分支并形成建议。双图、逐项修订、分支相容性检查和两阶段元评审共同承担科学解释与独立复核。

这一实现把大量科学判断转化为独立对象、角色任务和阶段完成条件。V2 保留上述方法思想，调整它们的组织方式：结论提前形成并持续更新，领域结构与多轮协作按其对结论的作用收敛。
